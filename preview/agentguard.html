AgentGuard

Make agent tool calls subject to explicit policies, limits and inspectable audit records. Boundaries before capability.

Control question

How do you ensure agent tool calls comply with explicit policies and limits?

Run inspection demo View repository

AgentGuard decides whether a specific tool call is permitted, under which limits, and records the reasoning so the decision can be questioned later. Each call is evaluated against a declared policy: role, tool, resource scope, and rate limit. A call that matches no rule is denied rather than permitted by default.

  • Default-deny policy engine — no rule means no access
  • Per-agent rate limits — boundary produces a refusal, not a timeout
  • HMAC-chained audit log — modified entries break verification
  • Human-in-the-loop approvals — approval required in policy, not separate workflow
  • Kill-switch coordination — instant halt across all agents

Enforcement layers

Four enforcement layers

Layer 1 · Policy

  • Role, tool, resource scope evaluation
  • Allow / block / review rules
  • Rate limits per caller and tool

Layer 2 · Audit

  • Hash-linked append-only log
  • Tamper-evident chain verification
  • Export to SIEM / GRC

Layer 3 · Approval

  • Human-in-the-loop decisions
  • Single-use, expiring approval tokens
  • Admin issuance only

Layer 4 · Kill switch

  • Instant halt across all agents
  • Durable state preserved
  • Resume after review
